## 1. Общие правила

- Базовый адрес в разработке: `http://localhost:5000`. Клиент Vue работает на `http://localhost:5173`.
- Формат тел запросов и ответов — JSON (`Content-Type: application/json`), имена полей в `camelCase`.
- Главный объект — заявка на ремонт / ТО, путь `/api/work-orders`. Справочник — оборудование, `/api/equipment`.
- Статусы только: `New`, `InProgress`, `Closed`, `Cancelled`. Подписи «Новая», «В ремонте», «Выполнена», «Отменена» — только на экране.
- **Метода `DELETE` нет.** Отмена заявки — `PATCH /api/work-orders/{id}/status` со статусом `Cancelled`, строка остаётся.
- Действие задаёт HTTP-метод, а не слово в пути: нет `/create`, `/update`.
- Назначение исполнителя и смена статуса — **два разных PATCH**.
- Все пути, кроме `POST /api/auth/login`, требуют входа (заголовок `Authorization: Bearer <токен>`). Без входа — `401`, без нужной роли — `403`. Права проверяет сервер (НФТ-2).
- Пустой список — `200` и `[]`, а не `404`. `404` — только когда нет записи с конкретным `id`.

### Коды ответов

| Код | Когда |
|-----|-------|
| `200 OK` | чтение или изменение прошло |
| `201 Created` | заявка создана, в заголовке `Location: /api/work-orders/{id}` |
| `400 Bad Request` | поля не прошли проверку (длина, пустое значение, нет такого `equipmentId`, неизвестный код статуса) |
| `401 Unauthorized` | не выполнен вход / неверный логин или пароль |
| `403 Forbidden` | вход выполнен, но роли или владельцу действие не разрешено |
| `404 Not Found` | нет заявки с таким `id` |
| `409 Conflict` | действие нарушает правила жизненного цикла (недопустимый переход, назначение не в `New`) |

## 2. Таблица API

### 2.1. Заявки на ремонт (главный объект)

| Метод и путь | Кто может | Тело | Успех | Возможные ошибки |
|--------------|-----------|------|-------|------------------|
| `GET /api/work-orders` | все роли | — (фильтры в query: `status`, `equipmentId`, `mine=true`) | `200`, массив заявок или `[]` | `400` (неизвестный статус в фильтре), `401` |
| `GET /api/work-orders/{id}` | все роли | — | `200`, одна заявка | `401`, `404` |
| `POST /api/work-orders` | `Foreman`, `Mechanic` | `title`, `equipmentId`, `description` | `201`, заявка с `id`, `number`, `status: "New"`, `assignee: null` | `400`, `401`, `403` |
| `PATCH /api/work-orders/{id}/assignee` | `Mechanic` | `assigneeUserId` | `200`, заявка с исполнителем, статус по-прежнему `New` | `400` (пользователь не слесарь / не существует), `401`, `403`, `404`, `409` (заявка не в `New`) |
| `PATCH /api/work-orders/{id}/status` | `Fitter` (свою: `InProgress`, `Closed`); `Mechanic`, автор-`Foreman` (`Cancelled`) | `status` | `200`, заявка с новым статусом | `400` (неизвестный код), `401`, `403` (чужая заявка / роль), `404`, `409` (недопустимый переход) |

### 2.2. Вспомогательные (для экранов)

| Метод и путь | Кто может | Тело | Успех | Возможные ошибки |
|--------------|-----------|------|-------|------------------|
| `POST /api/auth/login` | все | `login`, `password` | `200`, `token` и пользователь (`id`, `fullName`, `role`) | `400`, `401` |
| `GET /api/auth/me` | все роли | — | `200`, текущий пользователь (для шапки) | `401` |
| `GET /api/equipment` | все роли | — | `200`, массив оборудования для выпадающего списка или `[]` | `401` |
| `GET /api/users?role=Fitter` | `Mechanic` | — | `200`, список слесарей для «Назначить» или `[]` | `401`, `403` |

Справочник оборудования в семестре заполняется начальными данными (seed) при создании БД; методов изменения справочника через API нет.

## 3. Примеры JSON

### 3.1. Создать заявку — `POST /api/work-orders`

Запрос (мастер участка). Клиент **не** присылает `id`, `number`, `status`, исполнителя и автора — их определяет сервер.

```json
{
  "title": "Не включается шпиндель",
  "equipmentId": 3,
  "description": "После смены инструмента шпиндель не стартует, на пульте ошибка E-12. Станок остановлен."
}
```

Ответ `201 Created`, заголовок `Location: /api/work-orders/17`:

```json
{
  "id": 17,
  "number": "ЗР-2026-0017",
  "title": "Не включается шпиндель",
  "description": "После смены инструмента шпиндель не стартует, на пульте ошибка E-12. Станок остановлен.",
  "status": "New",
  "equipmentId": 3,
  "equipment": { "id": 3, "inventoryNumber": "ИНВ-04512", "name": "Токарный станок с ЧПУ 16А20Ф3", "areaName": "Токарный участок" },
  "createdBy": { "id": 2, "fullName": "Иванов А. П." },
  "assigneeUserId": null,
  "assignee": null,
  "createdAt": "2026-10-23T08:14:00Z",
  "updatedAt": "2026-10-23T08:14:00Z"
}
```

Объекты `equipment`, `createdBy`, `assignee` собираются сервером через JOIN для удобства списка; в таблице `work_orders` хранятся только ключи (см. [3НФ](data-model.md#4-проверка-третьей-нормальной-формы-3нф)).

Ошибка `400 Bad Request` (ФТ-3) — сообщения привязаны к полям, чтобы показать их у поля формы:

```json
{
  "status": 400,
  "title": "Ошибка проверки полей",
  "errors": {
    "title": ["Заголовок должен содержать от 5 до 80 символов"],
    "equipmentId": ["Оборудование с таким id не найдено"],
    "description": ["Описание должно содержать от 10 до 500 символов"]
  }
}
```

Ошибка `403 Forbidden` (слесарь или начальник цеха пытается создать):

```json
{ "status": 403, "title": "Нет прав на создание заявки" }
```

### 3.2. Список заявок — `GET /api/work-orders`

Примеры запросов:

```text
GET /api/work-orders                         все заявки (новые сверху)
GET /api/work-orders?status=New              фильтр по статусу (ФТ-11)
GET /api/work-orders?equipmentId=3           фильтр по станку (ФТ-11)
GET /api/work-orders?mine=true               «Мои заявки» слесаря (ФТ-12)
```

Ответ `200 OK`:

```json
[
  {
    "id": 17,
    "number": "ЗР-2026-0017",
    "title": "Не включается шпиндель",
    "status": "New",
    "equipmentId": 3,
    "equipment": { "id": 3, "inventoryNumber": "ИНВ-04512", "name": "Токарный станок с ЧПУ 16А20Ф3", "areaName": "Токарный участок" },
    "assigneeUserId": null,
    "assignee": null,
    "createdAt": "2026-10-23T08:14:00Z"
  }
]
```

Если заявок нет или фильтр ничего не нашёл — `200 OK` и `[]`.

### 3.3. Одна заявка — `GET /api/work-orders/{id}`

Ответ `200 OK` — объект как в 3.1. Если `id` нет:

```json
{ "status": 404, "title": "Заявка не найдена" }
```

### 3.4. Назначить слесаря — `PATCH /api/work-orders/{id}/assignee`

Запрос (механик цеха):

```json
{ "assigneeUserId": 5 }
```

Ответ `200 OK` — исполнитель назначен, статус **не меняется**:

```json
{
  "id": 17,
  "number": "ЗР-2026-0017",
  "status": "New",
  "assigneeUserId": 5,
  "assignee": { "id": 5, "fullName": "Петров С. И." },
  "updatedAt": "2026-10-23T08:30:00Z"
}
```

Ошибки:

| Ситуация | Код | Тело |
|----------|-----|------|
| мастер или слесарь вызывает метод (ФТ-9) | `403` | `{ "status": 403, "title": "Назначать исполнителя может только механик цеха" }` |
| `assigneeUserId` — не слесарь или не существует | `400` | `{ "status": 400, "errors": { "assigneeUserId": ["Пользователь не является слесарем-ремонтником"] } }` |
| заявки нет | `404` | `{ "status": 404, "title": "Заявка не найдена" }` |
| заявка уже не `New` | `409` | `{ "status": 409, "title": "Назначить исполнителя можно только для заявки в статусе «Новая»" }` |

### 3.5. Сменить статус — `PATCH /api/work-orders/{id}/status`

Взять в ремонт (назначенный слесарь):

```json
{ "status": "InProgress" }
```

Ответ `200 OK`:

```json
{
  "id": 17,
  "number": "ЗР-2026-0017",
  "status": "InProgress",
  "assigneeUserId": 5,
  "assignee": { "id": 5, "fullName": "Петров С. И." },
  "updatedAt": "2026-10-23T09:05:00Z"
}
```

Другие допустимые тела: `{ "status": "Closed" }` (слесарь, из `InProgress`), `{ "status": "Cancelled" }` (механик или автор-мастер, из `New`).

Ошибки:

| Ситуация | Код | Тело |
|----------|-----|------|
| слесарь меняет заявку, назначенную на другого (ФТ-8) | `403` | `{ "status": 403, "title": "Нет прав на изменение этой заявки" }` |
| мастер отменяет чужую заявку; начальник цеха меняет статус | `403` | `{ "status": 403, "title": "Нет прав на изменение этой заявки" }` |
| `New` → `Closed`, любое изменение из `Closed` / `Cancelled` (ФТ-10) | `409` | `{ "status": 409, "title": "Недопустимый переход статуса: New → Closed" }` |
| код статуса не из четырёх | `400` | `{ "status": 400, "errors": { "status": ["Допустимые значения: New, InProgress, Closed, Cancelled"] } }` |
| заявки нет | `404` | `{ "status": 404, "title": "Заявка не найдена" }` |

### 3.6. Вход — `POST /api/auth/login`

```json
{ "login": "ivanov", "password": "••••••••" }
```

Ответ `200 OK`:

```json
{
  "token": "eyJhbGciOi...",
  "user": { "id": 2, "fullName": "Иванов А. П.", "role": "Foreman" }
}
```

Неверный логин или пароль — `401` `{ "status": 401, "title": "Неверный логин или пароль" }`.

## 4. Чего в API нет и не будет

- `DELETE` на любой путь — отмена делается статусом `Cancelled`.
- `/api/work-orders/create`, `/api/work-orders/update` — действие задаёт метод.
- Общий `PATCH /api/work-orders/{id}` «обновить всё» — назначение и статус разделены, чтобы проверять права каждого действия отдельно.
- Приём `id`, `number`, `status`, `createdByUserId`, `assigneeUserId` в `POST` — сервер игнорирует их и ставит сам.
