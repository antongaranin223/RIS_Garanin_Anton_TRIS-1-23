# Известные дефекты и ограничения (ЛР12)

Найдены при сквозной проверке 07.11.2026 (стенд по README, Chrome, PostgreSQL 16). Исправлять все сразу не требуется: приоритетные пойдут в ЛР13.

Приоритет: **В** — мешает сценарию или безопасности; **С** — заметно пользователю, есть обход; **Н** — неудобство, косметика.

| № | Дефект | Как воспроизвести | Обход | Приоритет |
|---|--------|-------------------|-------|-----------|
| 1 | Учебный mock непригоден после ЛР11: в нём нет `POST /api/auth/login` и справочников, поэтому дальше экрана входа не пройти | `VITE_USE_MOCK=true` в `frontend/.env` → перезапуск Vite → вход | Работать с настоящим API (`VITE_USE_MOCK=false`, рабочий режим) | Н |
| 2 | Нет защиты от одновременной правки одной заявки: последний `PATCH` перезаписывает предыдущий без предупреждения | Две вкладки: механик назначает Петрова, в другой — Сидорова в ту же секунду | Список обновлять перед действием; в ЛР13 — токен конкурентности (`xmin`) и `409` | С |
| 3 | Список не обновляется сам: изменения других пользователей видны только после «Обновить» или F5. Кнопка по устаревшей строке получает отказ сервера (403/409) с текстом у строки | Механик и слесарь в двух окнах; механик отменяет заявку, слесарь жмёт «В ремонт» | Кнопка «Обновить» | Н |
| 4 | Номер `ЗР-ГГГГ-NNNN` выдаётся как «максимальный + 1»: при одновременном создании второй запрос получает `409 «Номер … уже занят»`, клиент не повторяет запрос сам | 8 параллельных `POST` (см. отчёт ЛР10): 5 × 201, 3 × 409 | Нажать «Создать» ещё раз; в ЛР13 — последовательность в БД или повтор на сервере | С |
| 5 | Фильтры «Статус» и «Мои заявки» работают в браузере; параметры `status`, `equipmentId`, `mine` из контракта ЛР2 сервер не обрабатывает, постраничной загрузки нет | `GET /api/work-orders?status=New` возвращает все заявки | На учебном объёме незаметно; НФТ-3 (500 заявок за 2 с) не замерялось | С |
| 6 | Нет фильтра по оборудованию для начальника цеха (ФТ-11 выполнен частично: есть только фильтр по статусу) | Войти `orlov` | — | Н |
| 7 | «Выйти» только удаляет токен в браузере; отозвать выданный токен на сервере нельзя, он действует до конца срока (8 ч) | Скопировать токен до выхода, после выхода выполнить запрос с ним → 200 | Короткий срок токена; при утечке — сменить `Jwt:Key` (все токены станут недействительны) | С |
| 8 | Токен лежит в `sessionStorage` и доступен скрипту страницы; защита держится на отсутствии XSS (весь текст через `{{ }}`) | — | Учебный компромисс курса | Н |
| 9 | `db/seed.sql` из ЛР9 несовместим с базой после миграций: повторно вставляет участки и падает на `areas_name_key` | Выполнить `seed.sql` после `dotnet ef database update` | Не выполнять: справочники вставляют миграции, `db/` — справка ЛР9 | Н |
| 10 | Если Vite занял не 5173 (порт занят), браузер блокирует ответы API (CORS), и экран пишет «Нет связи с сервером», хотя API работает | Занять порт 5173 другим процессом → `npm run dev` | Освободить 5173 или добавить адрес в `Cors:Origins` в `backend/appsettings.json` | Н |
| 11 | Справочник оборудования запрашивается при каждом открытии списка и формы — лишний запрос | F12 → Network при переходах «Список» ↔ «Создать» | — | Н |

Ошибки из прошлых работ, которые закрыты в ЛР12:

- назначение и смена статуса были доступны только через Swagger — теперь кнопки на экране по ролям;
- оборудование в форме вводилось числом `equipmentId` — теперь выбор из `GET /api/equipment` с инвентарным номером и участком;
- в списке был только `equipmentId` — теперь инвентарный номер, название и участок;
- флаг mock был константой в коде — теперь `VITE_USE_MOCK` в `.env`.
