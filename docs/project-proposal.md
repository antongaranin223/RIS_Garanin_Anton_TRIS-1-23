## 1. Название и организация

- Название системы: **«ТОиР-Цех»** — веб-платформа управления техническим обслуживанием и ремонтом оборудования.
- Организация / подразделение: машиностроительный завод «ТехМаш» (учебная), механосборочный цех № 2 и обслуживающая его служба главного механика (ремонтная бригада цеха).
- № из таблицы примеров: своя тема («Разработка веб-платформы управления техническим обслуживанием оборудования для промышленного предприятия»).

Полная тема включает паспорта оборудования, графики ТО, ремонты, заявки, историю неисправностей и отчётность по простоям. В семестре делается **ядро** — заявка на ремонт/ТО конкретной единицы оборудования. Остальное вынесено в запас под ВКР (п. 7).

## 2. Главная сущность и справочник

- Главный объект (одна запись процесса): **заявка на ремонт / техническое обслуживание** (work order) — «станок остановился / нужно ТО, кто взял, в каком состоянии работа».
- Справочник (вторая таблица, ссылка числом): **оборудование** — единица оборудования цеха (инвентарный номер, наименование, участок). Упрощённый «паспорт».
- Поле-ссылка (в JSON/БД): `equipmentId` (целое число > 0).

## 3. Роли и права

| Роль | Создаёт | Назначает | Меняет статус |
|------|---------|-----------|---------------|
| Мастер участка | да | нет | нет (только отмена своей заявки в `New`) |
| Механик цеха (диспетчер ТОиР) | да | да | нет (только отмена `Cancelled`) |
| Слесарь-ремонтник (исполнитель) | нет | нет | да — только своей заявки |
| Начальник цеха (сводка) | нет | нет | нет |

Исполнитель не назначает себя сам — исполнителя назначает механик цеха.

## 4. Сценарий в одно предложение

Мастер участка создаёт заявку на неисправный станок → механик цеха назначает слесаря-ремонтника → слесарь переводит заявку «в работу» и затем «выполнена».

## 6. Что не входит в семестр

1. Полные паспорта оборудования (характеристики, документы, фото) — в семестре справочник только с инвентарным номером, названием и участком.
2. Графики планово-предупредительного ремонта (ППР) и автоматическое создание плановых заявок.
3. Склад запчастей, списание материалов, закупки.
4. Отчётность и расчёт простоев (MTTR, MTBF, коэффициент готовности).
5. Интеграция с 1С/ERP, датчиками и SCADA.
6. Печать нарядов-допусков, мобильное приложение, SMS/e-mail-уведомления.
7. Сама физическая работа по ремонту.

## 7. Запас под ВКР

**Данные / процесс**

1. Графики ППР: плановые виды ТО по наработке/календарю с автогенерацией заявок.
2. История неисправностей по единице оборудования с классификатором причин отказов и анализом повторяемости.

**Связи с другими системами**

3. Интеграция с 1С:ТОИР / ERP (справочник оборудования, склад запчастей, списание материалов).
4. Приём сигналов от датчиков / SCADA (аварийный останов → автоматическая заявка).

**Масштаб**

5. Несколько цехов и площадок завода, иерархия «завод → цех → участок → оборудование», разграничение доступа по подразделениям.
6. Аналитическая отчётность по простоям (MTTR, MTBF, OEE) и дашборд для главного механика.

## 8. Чем не копия соседа

Типовые темы «заявки энергопредприятия» и «IT-хелпдеск» ведут обращения по участку/пользователю. Здесь главный объект — ремонт **конкретной единицы оборудования** (ссылка на станок по инвентарному номеру), роли производственные (мастер участка → механик цеха → слесарь-ремонтник), а смысл записи — факт простоя и восстановления оборудования, что задаёт основу для учёта простоев и истории отказов в ВКР.
