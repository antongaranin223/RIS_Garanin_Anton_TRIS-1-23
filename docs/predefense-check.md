### D-01. На свежей копии `dotnet ef database update` падает без `dotnet restore`

- **Приоритет:** 1 (запуск).
- **Шаги:** чистый профиль → шаги README 0–3 → `dotnet ef database update`.
- **Ожидали:** миграции применяются.
- **Получили:** `NETSDK1004: Assets file '…/obj/project.assets.json' not found`.
- **Причина:** `dotnet ef` не скачивает пакеты NuGet сам. У автора они уже были скачаны после прошлых сборок, поэтому ошибка не проявлялась.
- **Исправление (ЛР12):** в шаг 4 README добавлен `dotnet restore` с пояснением.
- **Повторная проверка:** 12.11.2026, клон `8955ae2`, чистый профиль: `Restored …backend.csproj`, затем обе миграции и `Done.`
- **Статус:** **закрыт**.

### D-02. `dotnet-ef` ставится версии 11, а проект на EF Core 10

- **Приоритет:** 6 (документация). Запуск не ломает, но расходится с README и рискованно для `migrations add`.
- **Шаги:** чистый профиль → `dotnet tool install --global dotnet-ef` → `dotnet ef --version`.
- **Ожидали:** `10.0.x`, как в таблице версий README.
- **Получили:** `11.0.0`. С ноября 2026 в NuGet вышел EF Core 11, и команда без `--version` ставит самый новый. `database update` при этом прошёл без предупреждений.
- **Причина:** версия инструмента в README не закреплена.
- **Исправление:**
  - шаг 0.4 README → `dotnet tool install --global dotnet-ef --version "10.0.*"`;
  - добавлена подсказка, как убрать уже установленную другую версию;
  - в таблице версий — «10.0.x (не 11)».
- **Повторная проверка:**
  - новый пустой профиль, команда из исправленного README → `Tool 'dotnet-ef' (version '10.0.15') was successfully installed`;
  - `dotnet ef database update` → `The database is already up to date`;
  - `has-pending-model-changes` → `No changes have been made to the model`.
- **Статус:** **закрыт**.

### D-03. Требование НФТ-3 (500 заявок за 2 с) не было проверено

- **Приоритет:** 6 (документация). В [`known-defects.md`](known-defects.md) №5 значилось «не замерялось».

### D-04. Ответы 415 и «нет такого адреса» не по-русски / без тела

- **Приоритет:** 7 (косметика).
- **Шаги:**
  - `POST /api/work-orders` с `Content-Type: text/plain`;
  - `GET /api/nope`;
  - `GET /api/work-orders/abc`.
- **Ожидали:** `ProblemDetails` на русском, как у остальных ошибок (НФТ-4).
- **Получили:**
  - `415` с `"title":"Unsupported Media Type"`;
  - `404` с пустым телом.

  Коды правильные, 500 нет. Экран Vue такие запросы не отправляет.
- **Причина:** стандартные ответы ASP.NET Core до входа в контроллер.
- **Исправление:** не делалось — косметика, а одна мелкая доработка ЛР13 требует согласия преподавателя.
- **Статус:** **открыт**, в [`known-defects.md`](known-defects.md) №12.

Остальные известные ограничения (одновременная правка, выдача номера при гонке, отзыв токена и др.) — в [`known-defects.md`](known-defects.md). Сценарий трёх критериев они не ломают.

## 4. Повтор трёх критериев ЛР1

Один новый `id` на чистом стенде соседа после исправлений, всё на экране Chrome.

> **id = 1 · number = ЗР-2026-0001**

| Критерий | Дано | Когда | Тогда | Факт |
|---|---|---|---|---|
| 1. Создать | вошёл мастер `ivanov` | заполнил форму: заголовок, «ИНВ-04512 · Токарный станок с ЧПУ 16А20Ф3», описание | `POST` 201, статус New | **да**. Экран: строка `ЗР-2026-0001 · id 1 · Новая`. Network: `POST /api/work-orders → 201`, `"id":1`, `"status":"New"` |
| 2. Назначить | запись `New`, вошёл механик `kuznetsov` | выбрал «Петров С. И.» → «Назначить» | исполнитель сохранён, статус остаётся New | **да**. Экран: «Петров С. И.», «Новая». Network: `PATCH /api/work-orders/1/assignee → 200`, `{"assigneeUserId":5}` |
| 3. В работу | вошёл назначенный `petrov` | «В ремонт» | статус InProgress | **да**. Экран: «В ремонте», кнопка «Выполнена». Network: `PATCH /api/work-orders/1/status → 200`, `{"status":"InProgress"}` |
| 3. Запрет | вошёл `sidorov` (другой слесарь) | экран; запрос в обход | кнопок нет; 403 | **да**. 0 кнопок в строке; `PATCH …/1/status` → **403** «Нет прав на изменение этой заявки: она назначена другому слесарю»; статус в БД не изменился (`InProgress`) |

Строка PostgreSQL:

```text
 id |    number    |   status   | assignee_user_id |   assignee   | updated
----+--------------+------------+------------------+--------------+---------
  1 | ЗР-2026-0001 | InProgress |                5 | Петров С. И. | t
```

`updated = t` значит `updated_at > created_at`: время изменения записывается.

**Без входа:**

```text
POST /api/work-orders (без Authorization)
{"title":"Требуется вход: передайте токен в заголовке Authorization: Bearer …","status":401}
→ HTTP 401
```

**Рестарт API:** процесс от 13:34:05 остановлен, `/health` не отвечает → новый процесс от 13:35:44. Вход `petrov`: `ЗР-2026-0001 · id 1 · Петров С. И. · В ремонте · [Выполнена]`.

Скриншоты: `reports/img/lab-13-1-create-form.png` … `lab-13-6-after-restart.png`.

## 6. Ответы на шесть вопросов

| Вопрос | Ответ своими словами | Где показать |
|--------|----------------------|--------------|
| Чем информационная система не сайт кафедры? | Сайт показывает одинаковые страницы всем. ИС ведёт **процесс со сменой состояния**: заявка проходит New → InProgress → Closed. У каждого шага есть хозяин — роль с правами, а данные хранятся и проверяются на сервере. | `docs/data-model.md` §6 (переходы), `docs/role-matrix.md` |
| Почему браузер не подключается к PostgreSQL сам? | Тогда пароль базы оказался бы в коде страницы у каждого пользователя, и любой мог бы выполнить `DELETE` в обход правил. Между браузером и БД стоит API: он проверяет вход, роль, поля и переходы, а пароль базы знает только сервер (user-secrets). | `docs/architecture.md` §4, `backend/Program.cs` (`AddDbContext`, `AddJwtBearer`) |
| Зачем два разных PATCH, а не одна «сохранить заявку»? | Это разные действия разных ролей: назначает механик, статус меняет слесарь. Отдельный адрес — отдельная проверка прав и отдельный код ответа (403 / 409). Общий «сохранить всё» позволил бы слесарю заодно переписать исполнителя. | `backend/Controllers/WorkOrdersController.cs` (`Assign`, `ChangeStatus`), `docs/api-contract.md` §3.4–3.5 |
| Почему название участка не пишут в каждой заявке? | 3НФ: участок — свойство станка, а не заявки. Заявка хранит только `equipment_id`, станок — `area_id`. Переименуют участок — меняется одна строка в `areas`, а не тысячи заявок. Название подтягивается JOIN-ом. | `docs/data-model.md` §4, `db/schema.sql`, `GET /api/equipment` |
| Почему пароль не кодируют Base64? | Base64 — запись байтов буквами, а не шифр: `VG9pci0yMDI2IQ==` раскодируется в `Toir-2026!` без ключа. Мы храним хэш PBKDF2 с солью (`PasswordHasher`): из него пароль не получить, только перебирать, и каждая попытка — 100 000 итераций. | `users.password_hash` в pgAdmin, `backend/Controllers/AuthController.cs`, отчёт ЛР11 §5 |
| Что сознательно не сделали и зачем это в списке на диплом? | ППР по графику, историю отказов, склад и 1С, датчики SCADA, несколько цехов, отчёты по простоям (MTTR/MTBF). Семестр — ядро процесса «заявка на ремонт», остальное — расширения, которые опираются на то же ядро. Их хватает на ВКР. | `docs/project-proposal.md` §6–7, `docs/kursovaya-zapiska.md` §7 |
