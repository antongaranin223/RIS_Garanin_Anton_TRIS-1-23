## 1. Цель

Зафиксировать в `/docs` архитектуру «ТОиР-Цех»: сущности и ключи (заявка на ремонт, оборудование, участок, пользователь), HTTP-запросы, которыми Vue (`:5173`) обращается к ASP.NET Core (`:5000`), и обосновать, почему браузер не обращается к PostgreSQL (`:5432`) напрямую. Каждый из трёх критериев ЛР1 должен быть связан с полем модели и запросом API.

## 2. Что сделали

1. Зафиксировали словарь проекта: Ticket → `WorkOrder` (`/api/work-orders`), Site → `Equipment` (`equipmentId`), роли `Foreman`, `Mechanic`, `Fitter`, `ShopChief` — [`docs/data-model.md`](../data-model.md), §1.
2. Описали четыре сущности с PK, FK и UNIQUE: `WorkOrder`, `Equipment`, `Area`, `User` — там же, §2.
3. Нарисовали ER-диаграмму (Mermaid + текстовый вариант) и подписали связи словами; исполнитель необязателен (`assigneeUserId` NULL) — §3.
4. Записали проверку 3НФ: название станка и участка хранится один раз, в заявке только `equipmentId` — §4.
5. Разделили `id` (машинный PK) и `number` (`ЗР-2026-0001`) — §5; описали статусы и разрешённые переходы по ролям — §6.
6. Составили контракт API: `GET` список и одна запись, `POST` создания с `201`, два отдельных `PATCH` (`/assignee`, `/status`), коды ошибок и примеры JSON; `DELETE` и `/create` нет — [`docs/api-contract.md`](../api-contract.md).
7. Нарисовали трёхузловую схему Vue `5173` → ASP.NET Core `5000` → PostgreSQL `5432` с примером запроса и подписью «архитектура web-ИС семестра» — [`docs/architecture.md`](../architecture.md).
8. Заполнили матрицу: три критерия ЛР1 и все ФТ-1…ФТ-12 → поле → запрос — [`docs/requirements-matrix.md`](../requirements-matrix.md).
9. Добавили ссылки на все документы в [`README.md`](../../README.md).
